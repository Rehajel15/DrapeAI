# DrapeAI

Learning project: an AI wardrobe app inspired by Alta. The goal is learning full-stack development, not a market-ready product.

## Features
- Digital wardrobe: add my own clothing items (photo + metadata)
- Outfit suggestions based on location, weather, occasion and personal style, using only wardrobe items
- Outfit preview as a collage (virtual try-on maybe later)
- Explanation of why a look works

## Tech stack
- frontend/: React Native with Expo (incl. web)
  - Styling: NativeWind (Tailwind classes) as the primary styling approach
  - UI components: React Native Reusables as the primary component library
- backend/: Django + Django REST Framework, Celery + Redis for background jobs
- AI: external APIs only (LLM etc.). No custom ML model in this project.

## Roadmap
1. Frontend and backend first, built together page by page
2. AI integration and API setup only after frontend and backend are done

## Current state
- backend/: Django 6.1 project. Project package is `config/` (settings, urls). SQLite database.
  - DRF and django-cors-headers are enabled. App `api` holds general endpoints under `/api/` (so far only `GET /api/health/`, used by the frontend connection demo). Feature apps bring their own model, serializer, view and urls.
  - App `accounts`: custom user model `accounts.User` (`AUTH_USER_MODEL`), based on `AbstractUser` without `username`. Login identifier is the email (stored lowercase, unique). The name asked for in the app is stored in `first_name`; `age` is an extra field (plausibility range 1-120, no minimum-age policy). `POST /api/auth/signup/` takes `{name, age, email, password}`, runs Django's password validators and answers `201 {id, name, age, email}` or `400 {field: [messages]}`. The model is registered in the admin.
  - Not built yet: login for existing accounts, tokens/sessions for the app, logout. Signing up only creates the account.
  - The dev database was recreated on 2026-11-13 for the custom user model; the old (empty) file is kept as `backend/db.sqlite3.bak` and can be deleted.
  - Celery and Redis are not installed yet.
  - `SECRET_KEY`, `ALLOWED_HOSTS` and `CORS_ALLOWED_ORIGINS` are loaded from `backend/.env` via django-environ (template: `backend/.env.example`, `.env` is gitignored). New secrets/config go into `.env` and `.env.example` the same way.
  - The Django autoreloader does not watch `.env`; restart `runserver` after changing it.
- frontend/: Expo SDK 58 (React 19.3, React Native 0.88, TypeScript). History: created from the SDK 58 template, downgraded to SDK 57 on 2026-10-21 (Expo Go for SDK 58 was not in the stores yet), upgraded back to SDK 58 on 2026-11-18. Expo Go for SDK 58 on Android: the official APK (Expo Go 58.0.x) is linked on expo.dev/go (github.com/expo/expo-go-releases); whether the Play Store version supports SDK 58 was not verified. Native tabs are imported from `expo-router/native-tabs`. Expo Router with file-based routes in `src/app/` (`_layout.tsx` = navigator); components, hooks and theme live outside `src/app/`. `typedRoutes` and `reactCompiler` are enabled in app.json. Files with a `.web.tsx` suffix are web-specific variants.
  - NativeWind 4.2.7 (Tailwind CSS 3.4) and React Native Reusables are set up via the manual install. Reusables components added so far: `text`, `card`, `button`, `input`, `label`, `icon`, `badge`, `progress` (in `src/components/ui/`). Icons come from `lucide-react-native` (with `react-native-svg`), rendered through the Reusables `Icon` component. NativeWind 4.2.7 officially only lists SDK 57; on SDK 58 it works (web, Android bundle), but on native in development react-native-css-interop triggers React Native 0.88's "ImageBackground is deprecated" warning at startup although the app does not use ImageBackground (nativewind/nativewind#1881). Harmless, not suppressed.
  - SDK 58 specifics:
    - React Native 0.88 uses the strict TypeScript API: a ref holds the element instance, so type refs as `React.ComponentRef<typeof X>` (in `useRef` and `React.RefAttributes`), not `X`. Components generated by the Reusables CLI may still use `React.RefAttributes<X>` and need this fix when a ref is passed (done in `input.tsx`). `app-tabs.web.tsx` works around the same problem in expo-router's `TabTriggerSlotProps`.
    - On web the dev server renders every page on the server first (`web.output: "server"`) and the browser then hydrates it. Server HTML and the first browser render must match, otherwise React logs a hydration error. So in code that renders on web: use `useColorScheme` from `@/hooks/use-color-scheme` (reports "light" until hydrated), not from `react-native`; and do not use React's `useId()`, because Expo Router 58 generates different ids on the server and in the browser (expo/expo#52249, open). `Field` derives its id from the label instead.
    - Routes are loaded on demand on web (async routes): the first visit of a route after starting the dev server can be slow or, rarely, fail once while it is being bundled.
    - Router calls are queued and applied after the current render ("deferred dispatch"); several calls in a row are applied in order, each against the state left by the previous one (e.g. `dismissAll()` then `replace()` in `signup.tsx`).
  - Config: `tailwind.config.js`, `babel.config.js`, `metro.config.js` (input `./src/global.css`), `components.json`, `src/lib/utils.ts` (`cn` helper), `src/lib/theme.ts` (`THEME`/`NAV_THEME`). `PortalHost` is rendered in `src/app/_layout.tsx`.
  - Add Reusables components with `npx @react-native-reusables/cli@latest add <component>`. Note: `src/components/ui/collapsible.tsx` is from the starter template, not from Reusables.
  - Routes are split into two groups below the root `Stack` (`src/app/_layout.tsx`): `(onboarding)` with `/` (welcome + name), `/age`, `/signup` (email + password), `/ready`; and `(tabs)` with `/home`, `/explore`, `/api`. The app always starts in the onboarding; nothing is remembered between launches yet. `/ready` leads to `/home` with `router.replace`.
  - `(tabs)` is wrapped in `<Stack.Protected guard={account !== null}>` in the root layout: the app behind the onboarding is only reachable after signing up in the current session. Without an account, Expo Router redirects every route into `(tabs)` (deep links, `/home` on web, a route restored by Expo Go on Android) to the root stack's anchor, the onboarding. Reason: on Android in Expo Go the app kept starting in the tabs, and the anchor alone did not prevent it. Side effect: `/home`, `/explore` and `/api` (incl. the backend demo) are only reachable after a sign-up; a full reload starts over, since nothing is persisted yet.
  - The root layout also exports `unstable_settings = { anchor: '(onboarding)' }`: Expo Router opens the anchor when the app starts without an initial URL (on Android it reads the URL with a 150 ms timeout) and uses it as the redirect target of the guard. Without it, the first group in Expo Router's sort order would be used (groups are sorted by name length, so `(tabs)` comes first).
  - Onboarding: the steps share their answers through `OnboardingProvider` (`src/components/onboarding/`), rendered in the root layout so that the guard can read `account`. `src/lib/auth.ts` (`signUp`) sends the answers to the backend in one request. Screens redirect to `/` if an earlier step is missing (e.g. page reload on web).
  - Design language (since 2026-11-18; the user rejected the earlier Vogue/editorial design and let Claude choose): modern, warm and friendly. Warm neutrals (linen background, charcoal text and primary buttons, white input fields) with one brand accent, terracotta (`brand` color, used for the progress bar, the "AI" badge, focus borders and the success badge). Rounded shapes: pill buttons (`rounded-full`), `rounded-2xl` inputs, round icon buttons. Brand motif: the `ClothingRail` illustration (garments in fabric colors on a rail, fits the name "Drape"). Copy is plain and friendly, no fashion-magazine tone. Works in light and dark mode; all colors come from the CSS variables in `src/global.css` (mirrored in `src/lib/theme.ts`), the fabric colors from `swatch.*` in `tailwind.config.js`.
  - Font: Plus Jakarta Sans, loaded with `useFonts` in `src/app/_layout.tsx` (400, 600, 700, 800) and mapped in `tailwind.config.js` as `font-sans`, `font-sans-semibold`, `font-sans-bold`, `font-sans-extrabold`. On native each weight is its own font file: use these classes instead of `font-semibold`/`font-bold`, and add `font-normal` where a Reusables component sets a weight through its text context (Button, Badge, Label).
  - Reusable pieces in `src/components/onboarding/`: `OnboardingScreen` (page frame: back button + progress bar for steps 1-3, scrolling content, footer above the keyboard), `Title`/`Subtitle`, `Field` (label, input, hint/error, optional trailing button), `PrimaryButton`/`IconButton`, `Wordmark` (logo), `ClothingRail`, `Reveal` (entrance animation: Reanimated on native, CSS classes on web). They are compositions of Reusables components and NativeWind classes; `ClothingRail` and the success badge on `/ready` are plain Views styled with NativeWind.
  - Icons inside a Reusables `Button` need a size class (e.g. `size-5`): the Button shrinks icons without one to 16px on web.
  - NativeWind's `darkMode: 'class'` follows the system theme on native by itself; on web the root layout mirrors it via `colorScheme.set()`.
  - The template's `AnimatedSplashOverlay` (Expo logo animation) is no longer rendered; the splash screen is hidden once the fonts are loaded.
  - The starter template screens in `(tabs)` still use `StyleSheet` and their own themed components.
  - Typed routes (`.expo/types/router.d.ts`): on Windows a running `expo start` can write wrong entries when files are added or moved (e.g. `/index` instead of `/`, components listed as routes), which makes `tsc` fail on valid hrefs. Restarting `npx expo start` regenerates the file correctly.
  - Backend base URL comes from `src/lib/api.ts` (`API_URL`): optional override `EXPO_PUBLIC_API_URL` in `frontend/.env`, otherwise the host from `Constants.expoConfig.hostUri` (PC's LAN IP in Expo Go) with port 8000, fallback `127.0.0.1` on web. `src/app/(tabs)/api.tsx` is the demo tab that calls `/api/health/`.
  - For Expo Go on a phone, Django must run on `0.0.0.0:8000` and the PC's LAN IP must be in `ALLOWED_HOSTS`. CORS only matters for the web version.
- frontend/AGENTS.md has Expo-specific rules. Most important: Expo changes every SDK, so check the versioned docs (https://docs.expo.dev/versions/v58.0.0/) instead of relying on memory, and add packages with `npx expo install <package>`, not `npm install`.

## Commands

Backend (run from backend/):
```powershell
.\venv\Scripts\Activate.ps1
pip install -r requirements.txt
python manage.py runserver 0.0.0.0:8000   # reachable from phones (Expo Go)
python manage.py makemigrations
python manage.py migrate
python manage.py test                                   # all tests
python manage.py test <app>.tests.<TestClass>.<method>  # single test
```

Frontend (run from frontend/):
```powershell
npm install
npx expo start          # dev server (press w for web)
npx expo start --web
npx expo lint
npx tsc --noEmit        # typecheck
npx expo install <package>
```
